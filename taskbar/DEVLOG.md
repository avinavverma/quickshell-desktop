# Taskbar / desktop dev log

Everything built and changed for the custom KDE desktop (Quickshell taskbar,
Switchboard, KWin tweaks): what works, bugs hit, failed attempts, and the fixes
that stuck. Newest notes are added at the bottom of each section.

Machine: CachyOS, KDE Plasma 6.8.2 (Wayland), KWin 6.8.2, Quickshell 0.3.2,
1920×1080, global animation speed `AnimationDurationFactor = 0.25` (4× faster
than default — this matters for every animation timing below).

## What exists now

### Projects (`~/Projects`)
| Folder | What it is |
|---|---|
| `switchboard/` | Quickshell window listing every project in `~/Projects` with on/off + "at login" switches, and per-module switches from a project's `modules.json`. Backend: `ctl.sh` (systemd user units `sb-<name>.service`). |
| `taskbar/` | The desktop shell: top bar + dock + Control Center (Quickshell). Started at login via `sb-taskbar.service`. |

### Taskbar pieces (`~/Projects/taskbar`)
- **Top bar** (`TopBar.qml`) — full-width, flush with the top edge, 36px, frosted. macOS layout: app name (left) · Now Playing (centre) · tray, Wi-Fi, Bluetooth, volume, battery, clock, window buttons (right).
- **Dock** (`Dock.qml`, `DockApps.qml`) — macOS-style: launcher, pinned apps (`dock.json`), running apps (dot), divider, minimised-window tiles, Trash. Auto-hides; stays up while the desktop is visible.
- **Control Center** (`ControlCenter.qml`, `WifiPage.qml`, `BluetoothPage.qml`) — opens from the Wi-Fi/Bluetooth icons; tiles for Wi-Fi, Bluetooth, DND, Night Light, Screenshot, brightness, volume, Now Playing.
- **Dock right-click menu** (`DockMenu.qml`), **media card** (`MediaCard.qml`).
- **Bridge** (`windows.py`) — Python; loads a KWin script that reports windows, runs window actions, holds Do Not Disturb, manages pins/Trash, feeds icon positions to `iconhelper`.
- **iconhelper** (`iconhelper/`, C) — tells KWin where each window's dock icon is (Plasma window-management protocol), so Magic Lamp minimises into the right place.
- **Modules** — `modules.json` decides what appears where (group: Dock / Top bar; section: left/center/right). Switchboard edits it live.

## Bugs hit and how they were fixed

1. **Bar showed an empty blob** — module slots were `visible: loader.item.visible`, but a child is never visible while its parent is hidden → deadlock. **Fix:** each module exposes an explicit `available` flag.
2. **Switchboard didn't pick up edits** — Quickshell's live reload didn't fire after whole-file rewrites. **Workaround:** restart the instance after big edits.
3. **Service name had a trailing `_`** (`sb-pill-bar_`) — `basename | tr -c` also translated the newline. **Fix:** bash parameter substitution.
4. **Dock icons were all generic** — Quickshell's `DesktopEntries` returned 0 entries here. **Fix:** the bridge resolves icons with `Gio.DesktopAppInfo`.
5. **No minimise animation at all** — KDE's Squash/Magic Lamp need the taskbar to publish icon positions; only Plasma's taskbar can by default. **Fix:** `iconhelper` speaks `org_kde_plasma_window_management.set_minimized_geometry` relative to an invisible 1×1 layer surface at the screen's top-left.
6. **Genie "too fast" no matter what** — I was setting `Duration`; Magic Lamp's key is **`AnimationDuration`**, and it's multiplied by the 0.25 global factor. **Fix:** set `AnimationDuration` (2000 → 1300 → 1000 → 920 by feel).
7. **Wi-Fi/Bluetooth KDE menus jumped from centre to top-right** — script moved them after mapping. **Fix (then superseded):** KWin window rule applies before first frame.
8. **KDE standalone menus slow (~500 ms)** — `plasmawindowed` startup; can't preload (single-instance, ignores 2nd launch) and KWin clamps off-screen moves (100px sliver). **Fix:** built native Control Center in the bar instead (instant).
9. **Spam-clicking dock icons misfired** — decisions used the dock's slightly stale copy of window state. **Fix:** `toggleapp` decides inside KWin with live state; 6 toggles in 129 ms alternated correctly.
10. **Cursor reverted to arrow after clicking dock icons** — Repeater over a plain JS array rebuilt every icon on each window change. **Fix:** `ScriptModel` keyed by app id (icons persist; verified 0 rebuilds across window changes).
11. **Dock lost all windows after many restarts** — KWin reuses script ids; `/Scripting/Script<id>.run()` hit a dead old script. **Fix:** unique script name per run + `Scripting.start()` instead of per-id `run()`.
12. **Two sets of window buttons** (top bar + window) — **Fix:** top-bar buttons only for title-bar-less windows; later borderless-maximised was turned off for consistency, so they never show.
13. **Genie drooped to the right** — target placed *below* the screen touches no screen edge; Magic Lamp's edge test then picks the wrong side. **Fix:** targets sit *on* the bottom edge (y = height − 2).
14. **KWin watch script silently half-dead** — `workspace.showingDesktopChanged` doesn't exist in the script API; the exception aborted the script mid-way (hooks after it never ran, Show Desktop detection never worked). **Fix:** connect via `on(obj, "signal", fn)` which skips missing signals.
15. **Bridge errors `TypeError: constructor returned NULL`** — PyGObject raises (doesn't return None) when a `.desktop` file is missing. **Fix:** `desktop_info()` wrapper.
17. **Dock stopped appearing at the bottom edge** — caused by the minimise workaround: the "set keep above / clear on restore" flag lived only in the KWin script's memory, so after taskbar restarts restored windows stayed *keep above*. A full-screen Claude window stuck on top covered the dock's edge trigger. **Fix:** cleared the stuck windows; the bridge now turns the temporary keep-above off ~1.5 s after a window minimises (verified: on at 0.3 s, off by 2.3 s, nothing left stuck).
16. **New icon pack (Mkos-Big-Sur-Night) not shown in the dock** — the theme was applied correctly; the taskbar loads icons once at start. **Fix:** `shell.qml` watches `~/.config/kdeglobals` and restarts `sb-taskbar.service` when `[Icons] Theme` changes (verified it keeps watching after KDE rewrites the file).

## Minimise animation not showing (Firefox / maximised windows) — investigation
Symptom: minimising (especially Firefox, or with a maximised app behind) showed no genie.

Failed theories / attempts:
- *Firefox's own (CSD) button is special* — moved Firefox to KDE's title bar; still failed. **Wrong.**
- *Target inside the window area blocks Magic Lamp* — moved targets below screen (caused bug 13), then reserved a 2px strip. Magic Lamp source shows it never checks this. **Wrong; reverted.**
- *Next window covers the animation* — partly right.

Root cause: **KWin bug 528416** (Plasma 6.8.2, confirmed, unfixed): when the window that receives focus next covers the screen, it's raised over the minimising window and hides its animation. My own tests had always set "keep above", which is why they worked.

**Workaround (current):** the KWin watch script sets *keep above* on a window when it starts minimising and clears it when restored (only if the script set it). Verified the flag flips correctly, and **confirmed working in real use** (Firefox minimise shows the genie, 2026-11-13).

Testing note: KDE won't let a script raise a window over the one you're actively using, so scripted "minimise and screenshot" tests can mislead unless the window is forced above.

18. **Dock icons jumped when a tile/app was removed** — **Fix:** `DockApps.qml` keeps leaving icons in the row (`displayKeys` + `leaving`) and animates a `presence` value: slot width and icon scale go 1→0 out / 0→1 in over 240 ms, so neighbours and the dock edge slide. (A first attempt failed to load — two `Component.onCompleted` handlers on one object — merged them.)

## Look
- **Font:** Inter (`inter-font` package) for all text — the open, SF-Pro-like font (SF Pro itself is licensed for Apple devices only). Icon glyphs come from FantasqueSansM Nerd Font via Qt's automatic fallback (`Theme.iconFont` kept for reference).
- **Glass:** `Theme.bg` is a light see-through tint (`#66202027`) over KWin blur, with a brighter 1px edge (`#3dffffff`) and `GlassSheen.qml` (soft top highlight) on the dock, Control Center, media card and dock menu. Small popups use the more solid `Theme.bgSolid` for readability.

19. **Media progress bar "not working"** — it only updated every 500 ms, couldn't seek, had no times, and hid itself until the length was known. **Fix:** 250 ms polling, click/drag to seek (`player.position` is writable when `canSeek`), elapsed/remaining labels, thicker on hover; card height 132 → 148. Not yet checked with live playback (no player was running).

20. **Progress bar full and "-0:00"** — Apple Music in Firefox reports `Position = 0` always and **no `mpris:length`**; the 0:07 was Quickshell's own estimate. **Fix:** bar only shows when `lengthSupported && positionSupported && length > 0`. Real fix for the browser: KDE's **Plasma Browser Integration** Firefox add-on (host part `plasma-browser-integration` is installed), which reports real position/length from the page's media.
21. **Accent colour** changed from pink `#fa586a` to dark purple `#6b3fa0` (taskbar `Theme.accent` and Switchboard); two hard-coded pinks replaced with theme-derived colours.

22. **Plasma Browser Integration installed → Firefox appears as two players**: Firefox's own (real title, `Position` 0, no length) and `plasma-browser-integration` (real position/length, but only the page title). **Fix:** `NowPlaying.qml` splits `player` (song info/controls, prefers the browser's own) from `progressPlayer` (same player if it reports progress, else a playing add-on player, matched by `dbusName`); `MediaCard` progress/seek use `progressPlayer`. Not yet seen live (playback stopped during the test).
23. **Cluttered top-right** — redesigned macOS-style: no dividers (`ModuleRow.dividers`), 20px spacing, rounded hover pill per item (`ModuleRow.hoverPills`), monochrome tray icons (`MultiEffect` colorization), icon-only Wi-Fi/Bluetooth/volume, battery as "100% 🔋", clock medium weight.

24. **Song name showed "Apple Music – Web Player"; length 5:48 for a 2–3 min song** — with the add-on installed the two Firefox players *swapped* roles (the add-on got real title/artist/art, Firefox's own only the page title). **Fix:** pick the playing player that actually has an artist (`hasInfo`), progress from any playing player with a length. The wrong length comes from Apple Music's page itself (both players report 348 s), so for `music.apple.com` the card shows **elapsed time only** (`NowPlaying.lengthTrusted`); other players keep the full bar + seek.
25. **Music kept stopping whenever the taskbar restarted (serious)** — apps launched from the dock ran *inside* `sb-taskbar.service` (Gio launch from the bridge), so every taskbar restart killed them (Firefox included). **Fix:** `launch()` now uses `systemd-run --user --scope --slice=app.slice … gtk-launch <app>`, giving each app its own scope like KDE does. The already-running Firefox was moved out with systemd `StartTransientUnit` + `PIDs`; verified its PID survived a taskbar restart.

26. **Accent follows the cover art** — `NowPlaying.qml` runs Quickshell's `ColorQuantizer` (depth 3, 64px) on the playing song's art, picks the most saturated mid-light colour (skips near-black/white and greyscale art), clamps lightness to 0.45–0.62, and fades `accent` over 600 ms. Default red `#e5484d` when nothing plays (Switchboard also uses this red). Verified: crimson art → `#cc192f`.

27. **No cover art for YouTube Music** — Firefox's own player only reports "YouTube Music"; the browser add-on has title/artist/length (correct: 3:25) but no `mpris:artUrl`. **Fix:** `NowPlaying.artUrl` = player's art → art from another player playing the same title → YouTube thumbnail `https://i.ytimg.com/vi/<id>/hqdefault.jpg` built from the `xesam:url` video id. All art (chip, card, Control Center) goes through `NowPlaying.artUrl`.
28. **ColorQuantizer can't load web images** ("Failed to load image from https://…") — web art is downloaded with curl into `$XDG_RUNTIME_DIR/taskbar-art/<md5>.img` (cleared at logout) and the quantizer reads that file (`NowPlaying.artFile`).

Note: apps launched from the dock inherit the bridge's stderr, so their warnings (e.g. Firefox's GTK icon-theme notices) show up in the taskbar log as `windows.py:` lines — harmless.

## Liquid Glass (KWin effect)
- Installed **kwin-effects-glass** from the AUR (`kwin-effects-glass-git`, builds 4v3ngR/kwin-effects-glass from GitHub; PKGBUILD reviewed — plain cmake build). Effect id `glass`; settings group **`[Effect-blurplus]`** (inherited name).
- KWin's built-in `blur` disabled (`[Plugins] blurEnabled=false`, `glassEnabled=true`) — they conflict.
- Start values: `RefractionStrength=0.6`, `RefractionEdgeSize=18`, `RefractionNormalPow=2`, `RefractionRGBFringing=0.15`, `RefractionBevelIntensity=10`, `EdgeLighting=true`, `EdgeLightingDock=true`, `RimSpecular=true`, `BlurStrength=6`, `DockBlurStrength=6`. Apply changes with `qdbus6 org.kde.KWin /Effects org.kde.kwin.Effects.reconfigureEffect glass`.
- **Undo:** `kwriteconfig6 --file kwinrc --group Plugins --key glassEnabled false; kwriteconfig6 --file kwinrc --group Plugins --key blurEnabled true; qdbus6 org.kde.KWin /KWin reconfigure`.
- **After KWin updates** the AUR package may need rebuilding (`paru -S kwin-effects-glass-git`) or it stops loading.
- **Top bar white outline:** Glass draws rims around every blurred panel, and on the full-width bar they traced the screen edges. Glass can only exclude by window *type* (bar, dock and Control Center are all "docks"). First tried: no blur on the bar (transparent, macOS-26 style). Then the bar was blurred again with **`EdgeLightingDock=false` and `RimSpecular=false`** — both were needed (edge lighting alone left a faint rim). Bar: blurred, faint tint (`Theme.barTint = #40000000`), no hairline, no outline. Trade-off: the dock and Control Center lose Glass's own rim highlights but keep refraction + the taskbar's own edge/sheen.
- Gotcha: in zsh, `G="cmd --flags"; $G ...` doesn't word-split — use a function (and not one named `g`, which is an alias here).

## Notes
- **Animation speed slider:** "Instant" sets `AnimationDurationFactor=0`, which disables *all* KDE animations (genie included). The intended setting is the notch left of Instant, `0.25`; Magic Lamp's `AnimationDuration=920` is tuned for that (≈230 ms). If the slider is moved, the genie length scales with it.

Old `NONE` entries were deleted.

36. **Current song (BAJESH VISHAY, "Naam Sujal and Hisab") found nothing** — YouTube Music joins artists with "and", LRCLIB lists "Naam Sujal, Hisab", and LRCLIB's search needs every word to match, so `artist title` returned 0 results (the exact lookup 404'd for the same reason, and the LyricsPlus server timed out). **Fix:** the search step now runs four searches in parallel (full artist + title, main artist + title, `track_name`+main artist, main artist + title without brackets), merges them, keeps synced results of about the right length and ranks exact title match, then matching main artist. 37. **Lyrics didn't appear after a shell reload while a song was already playing** — the lookup started only when the song *changed*, never for the song already playing at start-up. `Lyrics.qml` now also starts it on load. The LyricsPlus server is given 6 s (it sometimes spends 9 s timing out before saying "not found", and LRCLIB is only used after it answers).
38. **All lyric lookups run in parallel** — `lyrics-fetch.sh` now starts every way of finding the song at once (LyricsPlus with full names; LyricsPlus with main artist + title without brackets; LRCLIB exact with album; LRCLIB exact without album; four LRCLIB searches merged) and then takes the answers in priority order as soon as the higher ones are known, instead of trying them one after another. If the program stops, the grab and the virtual touchpad vanish and the real touchpad is used again. It also does the four-finger tap (`--tap4`) while running, since a taken touchpad can't be read by `touchpad-taps.py`. User picked the left edge.
